# DM-2026-004: Process artifacts are Markdown and JSON, not LaTeX

| | |
|---|---|
| Date | 2026-11-11 |
| Status | Approved by the repository owner |
| Affects | All `docs/DM-*.md`, `docs/VER-*.md`, `docs/REQ-*.json` |

## Purpose

The `systems-engineering` process framework lists LaTeX as the convention for
decision memoranda and verification documents. This repository is public,
small, and rendered mostly through GitHub. A decision was needed on whether to
follow the LaTeX convention or deviate.

## Options considered

1. **LaTeX source with committed PDF**, as the framework's artifact table
   lists. Produces formal, paginated documents. Requires a TeX toolchain to
   regenerate, and PDFs do not diff.
2. **Markdown for prose documents, JSON for structured ones.** Rendered by
   GitHub without a toolchain; every change is a readable diff; the
   verification matrix can be generated by a shell script and checked in CI.
3. **Markdown source, with PDF produced at release time** by the release
   workflow.

## Decision

Option 2 now, with option 3 available if a recipient requires PDF. The
requirements document stays JSON exactly as the framework's Phase 1 schema
specifies.

## Rationale

- The framework's own quality criteria for verification (Phase 4) require
  file paths and line numbers to be current. Only a format that can be
  generated and diff-checked by CI satisfies that continuously; a PDF cannot.
- MIL-STD-498 specifies content, not format. DI-IPSC-81442 is satisfied by
  any medium that carries the sections.
- The deviation is recorded here so the framework maintainer can decide
  whether Markdown should become an accepted convention (backport proposed
  to `systems-engineering`).

## Consequences

- `scripts/ver.sh` generates `docs/VER-2026-001.md` from the evidence
  anchors in `docs/REQ-2026-001.json` and fails if an anchor is missing.
- Document identifiers keep the framework's conventions: `REQ-YYYY-NNN`,
  `DM-YYYY-NNN`, `VER-YYYY-NNN`.
