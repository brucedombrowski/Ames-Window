## 1. Scope

### 1.1 Identification

This document applies to **Ames Window** version **v0.0.1**, identified by
git commit `ff2932c571b1245d6f711372fab50793fd77c3e0`. The software consists of two Rust crates,
`ames-core` and `ames-app`, producing one executable, `ames-window`,
for iOS, macOS, Windows, Linux and WebAssembly.

### 1.2 System overview

Ames Window is an interactive demonstration of the Ames window optical illusion: a
rotating trapezoid that appears to oscillate rather than spin. It has no
network capability, stores no data, and takes no input other than touch or
pointer gestures. The executable is self-contained.

### 1.3 Document overview

This SVD identifies and describes the software version named above. Section 3
lists the materials released, the files and third-party components that make
up the software, the changes since the previous version, installation
instructions and known problems. It is generated from the repository and is

#### 3.2.2 Third-party components

215 components across every target the source builds for, under
19 distinct licence expressions, all within the allowlist in
`deny.toml`. Exact versions and source checksums are pinned in
`Cargo.lock`. The complete record, including the dependency graph and
licence per component, is `sbom.cdx.json`.

The browser build draws on 54 of them, listed in
`sbom-web.cdx.json`. That file is what Cargo resolves for the browser
target, which is slightly more than what is delivered: it includes tools that
run only while building (procedural macros and build scripts) and a few
optional components that no enabled feature compiles. Nothing compiled into
the bundle is absent from it.

Some things in or behind the released programs are in none of the three
SBOM files (the third, `sbom-windows.cdx.json`, covers the Windows program
as `sbom-web.cdx.json` covers the browser build),
because they are not Cargo components.

- Both programs: the Rust standard library and compiler, at least version
  1.87 and otherwise as recorded in the build log of the release.
- The Windows program: Microsoft's C runtime, linked into
  `ames-window.exe` from the Visual Studio build tools on the build
  machine. The build log does not record their version. It records the
  build machine's image and that image's version, whose published software
  list gives the version of the tools.
- The browser bundle: the JavaScript glue `ames-window.js`, generated by
  `wasm-bindgen-cli` 0.2.130, a build tool pinned to that version; and the
  page `index.html` with its script, which are this project's own.

### 3.6 Installation instructions

**Web.** Unpack `ames-window-web.zip` into any directory served by a static
web server over HTTPS. No server-side code is required. Open `index.html`.

**iOS.** On a Mac with Xcode installed, run `scripts/ios.sh sim` for the
simulator or `scripts/ios.sh device` for a signed device build. The script
compiles with Cargo, assembles the `.app` bundle and installs it.

**Windows.** Unzip `ames-window-windows-x64.zip` and run
`ames-window.exe`. Nothing is installed. The program is not code-signed, so
Windows SmartScreen warns on first run; the README inside the zip explains.

**Other desktops.** Run `cargo run -p ames-app --release`.

**Verification.** Compare each file's SHA-256 against `SHA256SUMS` before
installation. The SBOM for the web bundle is `sbom-web.cdx.json`, and for
the Windows program `sbom-windows.cdx.json`.

**Removal.** Delete the installed files or the app bundle. The software writes
nothing outside its own installation directory.
