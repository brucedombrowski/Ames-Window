# DM-2026-001: The application has no network capability, permanently

| | |
|---|---|
| Date | 2026-11-11 |
| Status | Approved by the repository owner, recorded in GitHub issue #8 |
| Affects | REQ-2.1, REQ-2.2; `deny.toml`; CI job `no-network` |

## Purpose

Ames Window is an IT security compliance demonstration. Its value is the
process around it, which is easiest to show when the application itself is
trivially safe. A telemetry downlink was discussed as a hypothetical feature.
A decision was needed on whether network capability is ever in scope.

## Options considered

1. **Allow network features as Major changes.** Telemetry or update checks
   could be proposed and would go to the control board each time.
2. **Prohibit network capability permanently, enforced by tooling.** Any
   networking component fails the dependency policy; any socket code fails CI.
3. **Prohibit by policy only.** State the rule in documentation and rely on
   review.

## Decision

Option 2. The application never has network capability, inbound or outbound.
This is a charter item outside every change class. A project that needs
telemetry is a different repository.

## Rationale

- NIST SP 800-53 Rev. 5 CM-7, Least Functionality: the strongest form of the
  control is to have no capability to restrict. "No network code" is a claim
  that can be verified from the SBOM and the dependency policy rather than
  argued from a configuration.
- Every network control family (SC-7 boundary protection, SC-8 transmission
  confidentiality, and others) becomes not applicable with a one-line
  justification, which shortens any future System Security Plan.
- Option 3 depends on reviewers noticing a transitive dependency. The
  `tokio` crate is already present transitively for the browser build; only
  the tooling can tell that its `net` feature is off.
- Option 1 keeps the door open, which invites the request. Closing it
  removes a recurring agenda item from the control board.

## Consequences

- `deny.toml` bans 21 networking crates and denies the network features of
  `tokio` and `web-sys`. Verified to fail on three crates when an HTTP client
  is added.
- CI greps `crates/` for socket types and browser fetch calls.
- The SVD states the claim in section 1.2 of every delivery.
- Known limit: a renamed import of the standard library's socket types would
  evade the grep. Second-person review remains the control for that.
