# DM-2026-006: Wayland window decorations without a font parser

| | |
|---|---|
| Date | 2026-11-11 |
| Status | Approved by the repository owner; Normal change |
| Affects | RISK-2, RISK-6; `crates/ames-app/Cargo.toml`; `Cargo.lock`; `sbom.cdx.json`; closes #6 |

## Purpose

The weekly advisory scan reported RUSTSEC-2026-0192: `ttf-parser` is
unmaintained. It reached the build only through `winit`'s default feature
`wayland-csd-adwaita`, which draws client-side window decorations on Wayland
and uses a font parser to render the window title. A decision was needed on
how to respond.

## Options considered

1. **Keep the default feature and accept the advisory** with an `ignore`
   entry in `deny.toml`. Zero code change; the unmaintained component ships.
2. **Switch to `wayland-csd-adwaita-notitle`.** Same decorations, no title
   text, no font parser. Removes `ttf-parser`, `owned_ttf_parser` and
   `ab_glyph` from the tree.
3. **Disable client-side decorations entirely.** Smallest tree. On
   compositors that do not draw decorations (GNOME), the window has no frame
   and cannot be moved or closed with the pointer.
4. **Switch to `wayland-csd-adwaita-crossfont`.** Renders the title with the
   system font stack through FreeType, replacing a Rust parser with C
   libraries and a dynamic dependency on the host.

## Decision

Option 2. The window title is not shown on Wayland compositors that rely on
client-side decorations. The frame, close and move controls remain.

## Rationale

- NIST SP 800-53 Rev. 5 SI-2 prefers removing a flawed component to
  accepting it. Option 2 removes it at the cost of a title string on one
  desktop configuration, which has no bearing on the demonstration.
- NIST SP 800-53 Rev. 5 CM-7: fewer components is the cheapest security
  control. The change also removes two further components, reducing the SBOM.
- Option 4 trades a pure-Rust tree for C dependencies and loses the
  project's "no C code" property stated in the README.
- Option 3 degrades usability on a common desktop for no additional
  security benefit over option 2.

## Consequences

- `winit` is declared with `default-features = false` and the features
  `rwh_06`, `x11`, `wayland`, `wayland-dlopen`, `wayland-csd-adwaita-notitle`.
- The `ignore` entry for RUSTSEC-2026-0192 is removed from `deny.toml`.
  RISK-2 is closed in the register with this memorandum as the reference.
- The SBOM is regenerated; `docs/facts.json` carries the new component count.
- Issue #6 is closed as completed.
