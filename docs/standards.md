# Governing standards

The standards that bind this repository, and what each one is used for. Only
openly published standards are normative here: every entry below can be read
in full, free of charge, at the address given. Standards behind a paywall are
listed at the end as context only and bind nothing.

Requirement keywords follow BCP 14 (RFC 2119 + RFC 8174): SHALL, SHOULD and
MAY are normative only in ALL CAPS. The requirements themselves are in
[`REQ-2026-001.json`](REQ-2026-001.json); the evidence for each is in
[`VER-2026-001.md`](VER-2026-001.md), generated by `scripts/ver.sh`.

## Not applicable, with reason

| Standard | Why it does not apply |
|---|---|
| FIPS 140-3, Security Requirements for Cryptographic Modules | The application performs no cryptography. The only hash in the project is SHA-256 over files, computed by the build toolchain, not by the application. |
| NIST SP 800-171, Protecting CUI in Nonfederal Systems | The repository is public and contains no CUI. A filled-in System Security Plan for a real deployment would be CUI and lives outside this repository. See `configuration-management.md`. |
| NIST SP 800-53 control families on network protection (SC-7 and related) | The application has no network capability by charter (issue #8, DM-2026-001). The claim is enforced by `deny.toml` and CI, not inherited. |

## Context only, not normative here

These are cited by the process framework this repository follows but are not
freely available. They are listed so a reader knows
where the framework's vocabulary comes from. Nothing in this repository
depends on their text.

| Standard | Relationship |
|---|---|
| ISO/IEC/IEEE 29148, Requirements engineering | Source of the stable-identifier and traceability vocabulary used in REQ and VER documents |
| IEEE 1028, Software Reviews and Audits | Source of the review vocabulary in the change process |
| ISO/IEC 25010, Software Quality | Quality model vocabulary |
| ISO/IEC/IEEE 15288, System life cycle processes | Systems engineering vocabulary |
