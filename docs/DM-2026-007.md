# DM-2026-007: An agent holding a named role may review and approve

| | |
|---|---|
| Date | 2026-11-11 |
| Status | Directed by the repository owner |
| Affects | `docs/configuration-management.md`, REQ-3.2, issue #9 |

Numbers 005 and 006 are taken by memoranda on a branch not yet merged.

## Purpose

The change process required a second *person* to review every change. The
repository has one human, the owner, and most changes are written by AI
agents. Every change therefore waited on the owner. The owner's instruction:
"I don't want to impede process, just observe and direct."

## Options considered

1. **Keep human-only review.** Strongest separation of duties. Every change
   queues behind one person, which is the problem being solved.
2. **Drop review for agent-written changes.** Nothing waits, and nothing is
   checked by a second party either. Abandons AC-5 outright.
3. **Let an agent holding a named role review and approve**, provided it is
   not the author and its review is on the record.

## Decision

Option 3. A reviewer is a person, or an AI agent assigned a job title from
the roles table of the configuration management plan. An agent reviewer
satisfies the review step for Standard and Normal changes when all of these
hold:

- It is a different agent from the author: a separate session that did not
  write the change and starts from the diff, not from the author's reasoning.
- It states its job title, the change class it confirms, what it checked and
  its verdict, as a comment on the pull request.
- All machine checks pass.

Major changes stay with the control board, which is the owner. The owner
directing a change is the board's decision; a recorded direction is enough
and no further approval step waits on them.

## Rationale

- NIST SP 800-53 Rev. 5 AC-5 asks that no single party both makes and
  approves a change. It does not say the second party must be human. What
  matters is independence and a record, and both are required above.
- CM-3 asks for review, approval and a retained record of each change. The
  pull request comment is that record.
- The owner keeps every power that matters: the charter, the change classes,
  releases, and the ability to stop or reverse anything.

## Consequences and known limits

- Independence is weaker than between two people. Two agents built on the
  same model can share a blind spot. The mitigations are the machine checks
  and the reviewer starting from the diff alone. This is an accepted risk.
- GitHub cannot record an approving review from the account that opened the
  pull request, and agents here act through the owner's account. The review
  is therefore a comment, not a GitHub approval. A branch ruleset that
  requires an approving review (issue #9) would block every agent-reviewed
  merge, so that ruleset must either omit the approval requirement or wait
  until reviewer agents have their own account.
- REQ-3.2 is reworded from "a person other than its author" to "a reviewer
  other than its author". It stays open: nothing yet makes the rule
  impossible to bypass.
